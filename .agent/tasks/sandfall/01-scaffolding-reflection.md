## Deviations from the phase file

**One justified deviation: added `extend-exclude = [".agent"]` to `[tool.ruff]`.**

The phase file's spec for `[tool.ruff]` only listed `line-length` and `target-version`. With ruff 0.16, `ruff format --check .` discovered Python code blocks inside the markdown task-plan files under `.agent/tasks/sandfall/*.md` and wanted to reformat them (5 files), causing the format gate to fail. The `.agent/` tree is task/plan metadata, not project source — ruff should not touch it. Excluding it is the root-cause fix (not a warning suppression): `ruff check .` was already implicitly not flagging the markdown, but `ruff format` actively formats code fences in markdown since ~ruff 0.6.

The phase file's spec didn't anticipate this because it predates ruff format's markdown support being enabled by default. Future phases should keep `.agent` excluded. Other ruff config (`line-length`, `target-version`, lint selector) is exactly per spec.

This deviation did not change any of the five required gates' semantics for actual project source.

## Suggestions for future work / agent improvements

- **Phase-file / global**: when a phase spec lists `[tool.ruff]` config without an `exclude`, recommend including `extend-exclude = [".agent", "build", "dist"]` (or similar) preemptively. The agent prompt currently says "fix root cause rather than suppress" — adding a permanent exclude for non-source dirs is a legitimate root-cause fix, but the implementer would benefit from explicit permission to do so without treating it as a deviation. Could be captured in the project AGENTS.md under tooling.
- **Phase 02+ implementer**: the `[tool.ruff]` config now has `extend-exclude = [".agent"]`. Don't remove it; if more non-source dirs appear (e.g. `build/`, `dist/` from PyInstaller in phase 06), append to that list.
- **Phase 06 packaging note**: `*.spec` is intentionally tracked per `.gitignore` (won't be ignored). The packaging agent should commit the spec file.
- **mypy strict**: `mypy src` passes cleanly because there's only `__init__.py` and `__main__.py`. Once real modules land in phase 02, expect to add proper type annotations everywhere — strict mode is unforgiving. Plan phases should budget for that.
